## 5.53.2 改了什么

| 改动 | 位置 | 说明 |
|---|---|---|
| A 轮询刷新 | `client.js` DetailPane | AI 会话在的时候每 2.5 秒拉一次题，`review_count` 变了才替换 |
| B 批量分栏 | `client.js` `aiBody` + 新组件 `BatchSide` | 左栏「这次要练的 N 道」清单，右栏会话；38/62 分 |
| C 空库引导 | `client.js` 新组件 `EmptyGuide` | 三步引导 + 「＋ 录第一道」 |
| D `mb_diagnose` | `tools.js` | 一次往返拿「今天练什么 + 哪最弱 + 反复栽在哪」 |

### A：为什么是轮询，而不是「让 AI 通知界面」

`mb_review` 是**模型在会话里调的工具**，它跑在 DSH 主进程，面板只是同一个页面里的另一块 DOM —— 两者之间没有事件通道。真要推，就得让插件在 `apply()` 里挂一个跨进程的消息总线，或者让 `mb_review` 去 `fetch` 面板的内部接口。两个都比「2.5 秒拉一次 `/api/mistakes/{id}`」复杂一个量级，而这道请求是单行主键查询（`get_mistake`），代价可以忽略。

两个细节：

1. **第一次 tick 只记基线**。打开详情时本来就是最新的，不记基线会立刻触发一次无意义的 `onChanged()`。
2. **值没变就返回旧对象**（`setItem(old => ...)`）。不这么做，每 2.5 秒都会拿到一个新对象，整棵详情重渲染 —— 图片、KaTeX 公式全部重算。

### B：为什么批量用 38%，单题用 50/50

单题复习时左栏是完整详情（题干、答案、图片、历史），值得一半宽度；批量复习时左栏只是「这次练哪几道」的清单，每行一行题干 + 一个理由，38% 够用，剩下 62% 留给对话 —— 批量场景下对话更长（一道接一道）。窄屏（≤760px）仍然上下堆叠，`.mb-aiduo.batch` 要显式再声明一次，因为它的特异性比 `.mb-aiduo` 高，媒体查询里的规则盖不住它。

### C：为什么判断空库不能看 `total`

`total` 是**筛选之后**的数量：库里 9 道题，搜一个不存在的词也是 `total: 0`。拿它当「库是不是空的」会让引导在筛选无结果时也冒出来。所以空态分支先看有没有任何筛选条件（`qText` / 学科 / 状态 / 错因 / 时间范围 / 知识点 / 标签 / 未归类），一个都没有才显示 `EmptyGuide`。

### D：为什么是「一个工具调两个接口」，不是新开 /api/diagnose

诊断需要的东西 `/api/brief` 和 `/api/analytics` 已经全都给了（brief 有 `counts`/`items`/`patterns`/`weak_points`/`sample`，analytics 有 `by_step`/`weak_points`/`sample`）。再开一个后端接口，等于把这两份数据复制一遍、再写一遍测试。工具里 `Promise.all` 两个请求、拼一段文本，二十行就够了 —— 而且以后简报多了字段，诊断自动就有。

空库分支单独处理：`counts.active === 0` 时正文写「题库还是空的 —— 先录第一道。」、下一步写「面板点「＋ 新建」录一道，或者把题目/截图发我，我用 mb_add 帮你录。」，并且**不念**「样本还少」那句 —— 一道题都没有的时候谈样本量是废话。
