# 5.47 从「功能很多」回到「用得下去」：三件事（v0.50）

> 本文件是[错题本 README](../../README.md)的拆分文档。含 5.47 节。上一版见 [v0.49.md](v0.49.md)。

## 5.47.1 为什么要做这一版

用户问「对我的这些功能进行分析并向我提出建议」。我把运行中的库和代码都量了一遍，结论很不体面：**近 40 个可操作点，只有 9 道题**，而且闭环末端全是 0（0 变式、0 试卷、0 别名、0 掌握、再战区 0 条）。功能不是不够，是**走不到**。

清点出五个真问题：

| # | 问题 | 证据 |
| --- | --- | --- |
| 1 | 录入留下半成品题 | id 14 只有题干 + 来源「壁」，答案 / 解析 / 我的答案全空 |
| 2 | 两套「未分类」并存 | 空串 5 道 + 字面「未分类」1 道，`GROUP BY` 直接分裂成两个桶 |
| 3 | 标签退化成第二个知识点 | 12 个标签**各只挂 1 题**，复用率为 0 |
| 4 | 掌握门禁在 9 题规模下数学上到不了 | `MASTERY_MIN_MISTAKES=3` + 每道连对 2 次 + 稳定性 ≥21 天 |
| 5 | 分析页在 4 次复习时照样给结论 | 样本量没有任何闸门 |

这一版只做能直接解掉 1 / 2 / 4 / 5 的三件事，**不新增任何功能**。

### 掌握门禁自适应

```python
MASTERY_SCALE_MISTAKES = 30
MASTERY_SMALL = {"min_mistakes": 2, "min_stage": 2, "min_stability": 7.0}

def mastery_thresholds(total_mistakes: int) -> dict:
    small = total_mistakes < MASTERY_SCALE_MISTAKES
    th = dict(MASTERY_SMALL) if small else {
        "min_mistakes": MASTERY_MIN_MISTAKES,
        "min_stage": MASTERY_MIN_STAGE,
        "min_stability": MASTERY_MIN_STABILITY,
    }
    th["mode"] = "small" if small else "full"
    th["total_mistakes"] = total_mistakes
    th["scale_at"] = MASTERY_SCALE_MISTAKES
    return th
```

**为什么按题量分档，而不是把门禁直接调低**：把阈值一次性降到 2 题 / 7 天，等于让 30 题以后的人也按玩具标准判定「已掌握」。分档让门禁**随库一起长大**：题库小的时候它够得着，题库大的时候它仍然是原来那个严格标准。

**为什么是 30**：`MASTERY_MIN_MISTAKES=3` 在 30 题规模下意味着「每个知识点平均 10 道」才可能通过，这是合理的严格度；低于 30 题时任何知识点都凑不出 3 道，门禁就只是摆设。

### 录入继承上次值

```javascript
const LAST_VALUES = {};

function emptyForm(initial) {
  const it = initial || {};
  const reuse = it.id ? {} : LAST_VALUES;
  return {
    subject: it.subject || reuse.subject || '',
    knowledge: it.knowledge || reuse.knowledge || '',
    source: it.source || reuse.source || '',
    mistake_type: it.mistake_type || reuse.mistake_type || '',
    difficulty: String(it.difficulty || reuse.difficulty || 3),
    // 题干 / 答案 / 标签 / 状态不继承
  };
}
```

**只继承「维度」不继承「内容」**：学科 / 知识点 / 来源 / 错因 / 难度是同一批作业共有的属性，一次录入 20 道题时它们几乎不变；题干、答案、标签、状态每题都不同，继承反而添乱。

**只在新建时继承**：`it.id` 存在（编辑已有题）时 `reuse = {}`，否则编辑一道老题会把它的字段覆盖成上次录入的值。

### 分析页样本闸

后端算 `sample`，前端只负责显示 —— 这样 CLI / agent 调 `/api/analytics` 也能拿到同一个判断，不必各自实现一遍阈值。`enough = reviews >= 20`，不足时 `note` 直接是一句人话：「样本还少：已复习 N 次，至少 20 次才看得出趋势，下面的比例先当参考。」

## 5.47.3 现场数据卫生

迁移前留了快照 `data/mistakes.db.bak-v050-20261024-125039`，然后：

| 动作 | 结果 |
| --- | --- |
| `migrate_v050()` | 5 行空学科 → 「未分类」，学科桶变成 未分类 6 / 数据结构 1 / 物理 1 / 英语 1 |
| 手工 `UPDATE ... SET source='' WHERE source='壁'` | 9 行来源全空（那是个手滑写进去的单字） |

**为什么脏值手工清而不是写进迁移**：迁移是给所有用户跑的，只该处理**语义等价**的归一（空串 = 未分类）；「壁」这种是个人手滑，写进迁移会让别人的库被误改。
