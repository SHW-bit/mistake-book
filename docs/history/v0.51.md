## 5.48.1 三个真问题

用户说「我要放大 ai 在我这的作用，做智能错题本」。清点当时的 AI 面：13 个 `mb_*` 工具、两条预设（复习 / 答疑）、`SKILL.md` 一份。看着不少，但三处卡着：

| 问题 | 具体表现 |
|---|---|
| **判分不留痕** | `review_logs` 只有 `result` / `rating` / `stage` / `interval_days` / 两个 FSRS 快照。学生怎么错的、靠没靠提示、为什么给这个档 —— 全丢。下次想答「这次和上次是同一个原因吗」，没数据 |
| **开场没方向** | `mb_due` 只给一串到期题，不解释为什么是这几道；`mb_plan` 只给按天的数量。学生问「今天练什么」，模型只能念清单 |
| **录入全靠手敲** | 一道题 11 个字段，`mb_add` 一次只收一道。整页试卷或一张截图进来，得人肉拆 |

### 为什么 `hints` 默认是 `-1` 而不是 `0`

`0` 的语义是「零提示自己做对」。老记录没有这个信息，如果默认 0，历史上所有「不知道用没用提示」的复习都会被算成零提示做对 —— 正确率凭空变好。

所以默认值取 `-1`（未记录），统计时只收 `hints >= 0` 的行。代价是**老数据永远补不回来**，零提示做对率只能从 v0.51 之后的复习开始积累。这是有意的：假数据比没数据更坏。

### 为什么 `brief` 不新建一张表

简报是**派生视图**，不是事实。今天最该练哪几道，完全由「到期时间 + 知识点正确率 + 断点历史」现算得出，落库只会多一份需要同步的缓存，还会在复习后立刻过期。所以 `brief()` 每次现算，不落库、不加表。

### 为什么录入 skill 不做 OCR

零第三方依赖是硬约束，OCR 库（tesseract / PaddleOCR）都是重依赖。DSH 的模型本身能读图，所以路径是「模型读图 → 抽成字段 → `mb_batch` 预览 → 确认入库」，识别能力交给模型，`app.py` 只负责校验与落库。读不了图时（纯文本模型）就退化成「只存图、题干留空」，事后手补。
