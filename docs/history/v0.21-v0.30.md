> 本文件是[错题本 README](../../README.md)的拆分文档。5.16–5.29。

## 5.16 DSH 插件：预设 + 工具（v0.21 阶段一）

5.6 那条路是「让 agent 跑 `python mb.py`」——能用，但每步都要过 shell，且工具面是全量的（bash、文件读写、子 agent 全都在）。v0.21 起补上 StudyMate 那套做法的第一层：**把错题本变成 DSH 里的一条预设 + 一组专用工具**，模型直接调，不过 shell。

三层结构（照 StudyMate 的 ADR 拆的）：

| 层 | 内容 | 本仓库状态 |
|---|---|---|
| ① 预设 = 身份 + 工具面 | 两条 cordis 预设行，各挂 4 个子插件 | ✅ 阶段一 |
| ② 面板 = 嵌宿主会话 | Client 插件，把复习界面塞进 DSH 侧栏 | ✅ 阶段二（见 5.17） |
| ③ 数据 = 按需取 | `app.py` 的 30 多个 `/api/*` | ✅ 已有 |

### 5.16.1 两条预设

| preset id | 名称 | order | 技能 | 工具 |
|---|---|---|---|---|
| `mistake-review` | 错题复习 | 40 | `mistake-review-loop` | 6 个 `mb_*` |
| `mistake-qa` | 错题答疑 | 41 | `mistake-qa` | 6 个 `mb_*` |

两条预设的子插件行完全同构，只有 persona 与技能目录不同：

```yaml
- id: persona                    # 身份：复习教练 / 就地答疑
  name: "@deepseek-ai/dsh-persona"
- id: skill-filesystem           # 只挂一个技能目录，不扫默认根
  name: "@deepseek-ai/dsh-skill-filesystem"
- id: tool-skill                 # 让模型能 skill 加载
  name: "@deepseek-ai/dsh-tool-skill"
- id: mistake-book-tools         # 6 个 mb_* 工具
  name: "dsh-mistake-book/tools"
```

**没有** bash / 文件读写 / 搜索 / web / 子 agent / plan / todo ——删行才是配置层的保证，不是提示词祈祷。

### 5.16.4 验证

- 假 ctx（`{tools:{register}}`）直接 `import()` → 注册 6 个，description 全 ≤ 120 码点、无换行。
- 真打 `127.0.0.1:8000`：`mb_due`/`mb_search`/`mb_get`/`mb_stats` 四视图输出正确；`mb_add` 建 #8 → `mb_review` 回「下次复习 2026-10-25 · 阶段 1」→ `mb_get` 历史正确 → 删除并清空回收站。
- 顺手修掉一个**时间相关的脆弱测试**：`test_plan_buckets_due_into_days` 用 SQLite 的 `datetime('now','+3 days')`（UTC）造数据，而 `plan()` 按本地时间分桶。UTC+8 下当地 0:00~8:00 之间两者差一天，测试会莫名报 `0 != 1`。已改为在 Python 里按本地时间生成戳（`_stamp()`）。
- 期间修掉两个字段名 bug：`/api/stats` 的 `by_subject` 元素键是 `subject` 不是 `name`；`/api/mastery` 的 `pending` 元素键是 `knowledge` 不是 `point`。

### 5.16.5 为什么这么做

- **零依赖**：profile 的 `node_modules/@deepseek-ai` 下只有 `cosmokit`/`schemastery`，pnpm 严格布局解析不到 `dsh-tools`。所以工具定义手写裸对象（`parameters` 用裸 JSON Schema），不 import 任何 `@deepseek-ai/*`——StudyMate 的 `lib/tools/define.ts` 是同一口径。
- **工具行写在预设里，不写全局**：全局挂会让工具出现在所有会话里，模型在写代码时也可能去调 `mb_add`。写进预设 = 只有选了这条预设的会话才有这 6 个工具。
- **服务没起就自动拉起**：`ensureServer()` 先探 `/api/health`，不通就 detached spawn `python app.py` 再轮询 12 秒。用户不必先开终端；拉起失败也不抛，让真正的请求去报错。
- **不做 iframe 嵌页面**：iframe 只能「看」，不能把错题喂给模型。阶段二要的是面板里嵌宿主自己的会话（StudyMate 的 `conversation.content` + `SessionProvider`），那是另一件事。

### 5.16.6 已知限制

- 改完 patch 必须重启 DSH；没有热重载（`dsh-app-boot` 里没有任何 watcher）。
- **裸行加不进新条目**：profile 的 `cordis.patch.yml` 是「补丁」不是「条目表」。`- id: xxx` 这种裸行只用来**覆盖已存在**的同 id 行；基础树里没有这个 id 时，`@deepseek-ai/cordis-plugin-include` 的 `applyEntryPatches` 会 warn 一句 `patch: entry "xxx" not found` 然后**静默丢弃**，不报错、不中断启动。新增必须写成 `- insert:` + 缩进 4 格的条目列表。本机踩过一次：两条预设裸行追加后重启，选择器里空空如也；同文件里 `dsh-context`、`dsh-font-adjust` 两行也是这么死的（基础 bundle 里已没有这两个 id）。
- **怎么自查**：不必重启也能验。用 `@deepseek-ai/dsh-app-boot` 的 `loadProfileDirectory("dsh", <profile目录>, "<安装目录>/package.json", {userLayer:true})` 拿到 `layers` 与 `patches`，再 `composeEntries([layers.flatMap(l=>l.patches), patches], warn)`，warn 里出现 `entry "xxx" not found` 就是死行。
- **折行 plain 标量会让 StudyMate 整个跳过原生加载**：某些 YAML 序列化器会把长描述按 ~80 列折成两行（`descriptionEn: ... native` + 缩进续行 `multimodal model`）。这在 YAML 里合法、宿主解析没问题，但 `@yunmiao/studymate` 启动时用自带严格解析器读**整份** `cordis.patch.yml`，遇到多行 plain 标量就抛 `缩进比同级多了 2 个空格：同级键必须对齐（多行 plain 标量也不支持）`，然后 `已跳过原生加载` —— 结果是「学习模式」「答疑模式」两条预设**一起消失**，看起来像被删了。修法：把续行拼回上一行（语义等价），`node tools/fix-cordis-patch-fold.mjs` 幂等处理（块标量 `>-` / `|` 的内容不动）。定位方法：`node` 里 import 插件的 `bin/dsh-plugin.mjs`，用假 ctx（`get` 返回 `{name:'desktop',home}`、`agentPresets.register` 收集）跑 `apply()`，`console.warn` 里就有真实报错。
- 只有选中「错题复习」或「错题答疑」预设的会话才有这 6 个工具。
- 阶段一没有界面：复习仍然在对话里进行，没有侧栏面板。
- `mb_add` 不接受图片（Data URL 太长，不适合走工具参数），要加图还是用网页。

## 5.17 DSH 面板：把复习界面塞进侧栏（v0.21 阶段二）

阶段一给了模型工具面，但「看错题、点开一道、评分」还是得开浏览器。阶段二补的是 5.16 那张表里的第 ② 层：**一条 DSH 客户端插件**，在侧栏加一个「错题」入口，面板里左边列出错题、右边看题与评分，需要时把宿主的会话正文嵌进右栏让 AI 带着复习。

### 5.17.1 为什么拆成「根行 + 预设行」

客户端插件的发现机制很窄，读 `dsh-client-modules/lib/index.js` 得到三条硬约束：

| 约束 | 源码位置 | 后果 |
|---|---|---|
| 只扫**根 loader 行** | `resolveSource(entry)` 遍历 `this.ctx.loader.entries()` | 预设里动态 mount 的行（`dsh-mistake-book/tools`）永远发现不到客户端半 |
| 行名必须是**裸包名** | `locatePkgJson` → `exactPackageSpecifier` 对含 `/` 的子路径返回 `undefined` | 根行写成 `dsh-mistake-book/tools` 会被**静默跳过**，不报错 |
| 必须有 `exports["./client"]` 且 `dsh.client.platform === "web"` | `parseDshClient` / `clientExportOf` | 缺一个就整条不加载 |

所以本包的形态是：**同一个 npm 包，挂两次**。

| 行 | 行名 | 导出 | 干什么 |
|---|---|---|---|
| 根行 `mistake-book-panel` | `dsh-mistake-book`（裸名） | `exports["."]` → `lib/plugin.js` | 只挂「建复习会话」路由；客户端半也随这一行被发现 |
| 预设行 `mistake-book-tools` | `dsh-mistake-book/tools` | `exports["./tools"]` → `lib/tools.js` | 8 个 `mb_*` 工具，按预设作用域挂 |

**为什么工具不写在根行**：根行是全局的，工具挂上去就会出现在所有会话里（写代码时模型也可能去调 `mb_add`）。工具面必须跟着预设走——这是阶段一定下的规矩，阶段二不改它。

### 5.17.2 面板做了什么

> v0.23 起这个面板已补齐网页版除组卷打印外的全部视图（六个页签），5.17.2 描述的「左列 + 右栏」是阶段二的形态，最新结构见 **5.19** 节。

`lib/client.js`（阶段二时约 420 行，无构建步骤，纯 `window.__ModuleLoader__.load()` 登记）：

- **两个座位**：`main`（keyed 面板，`key: 'mistake-book'`）与 `sidebar.panellist`（`id: 'mistake-book'`、`order: 41`、`label: '错题'`）。点侧栏那行由宿主调 `ctx.layout.selectPanel('mistake-book')`。
- **左栏列表**：`GET /api/mistakes?due=1&page_size=50`（「全部」分段去掉 `due`），题面两行截断，元信息显示学科 / 知识点 / 下次复习日。
- **右栏详情**：题目 → 我的答案 → 「看答案与解析」折叠 → 错因 → 知识点 → 四档评分（忘了 / 模糊 / 记得 / 简单）→「让 AI 带我复习这道」。
- **评分**：`POST /api/mistakes/<id>/review`，回执里带 `next_review_at`，就地显示「已记录 · 下次 10-24」并刷新列表（这道通常就离开了到期集合）。
- **样式**：全部用 `--mb-*` 变量并带兜底值，跟随宿主的明暗主题；`<style>` 在工厂物化时注入一次（`id="dsh-mistake-book-css"` 去重）。

**为什么组件不用 `React.createElement('div.cls')`**：`createElement` 会把 `'div.cls'` 整个当标签名，造出一个没有 class 的未知元素——CSS 一条都不生效，DOM 里却看着还在。所以文件顶部有个 20 行的 `h(sel, props, ...kids)` 自己拆 `tag.class`。

### 5.17.3 数据为什么也要过宿主（CORS）

面板跑在 DSH 的网页里（`http://127.0.0.1:<随机端口>`），错题本服务在 `http://127.0.0.1:8000` —— **两个 origin**。而 `app.py` 不发任何 CORS 头（它只服务同源的网页版），于是浏览器直连 8000 会被同源策略拦掉：GET 读不到响应体，带 `content-type: application/json` 的 POST 连预检都过不去。

**给 `app.py` 加 CORS 也能通，但没这么干**：那样任何本机网页都能读走整个错题本、还能提交评分。为了一块面板把本地库敞开，不值得。所以数据也由宿主转发：

```
面板 ──fetch('/api/mistake-book/data?path=%2Fapi%2Fstats')──▶ DSH 宿主（同源）
                                                              │ 取插件行 config.url
                                                              ▼
                                                        app.py :8000
```

- 路由：`GET|POST /api/mistake-book/data`，真实路径放 `?path=`（`encodeURIComponent` 过）。
- **只放行本服务的 `/api/*` 相对路径**（`isAllowedPath`）：绝对地址、`//`、`..`、裸 `/api/` 一律 400。不做这个检查，`?path=` 就是个 SSRF 口子。
- 上游报错包成 `502 + {code:'upstream-failed', message}`，面板把这句话原样显示。
- 客户端只多一层 `data(path, init)`（`api(DATA_ENDPOINT + '?path=' + encodeURIComponent(path), init)`），四处调用点换成它；`SESSION_ENDPOINT` 那条仍是相对路径直呼宿主，不过代理。

### 5.17.4 建会话为什么必须走宿主

浏览器的 `sessions.create` 只序列化 `{ workspaceId, cwd, sessionId }`，会把 `agentPreset` **静默丢掉**。面板自己建的会话不带「错题复习」预设，工具面与 persona 全都不在——看起来能用，实际是个裸会话。

所以 `lib/session.js` 在宿主侧开了一条路由 `POST /api/mistake-book/session`，一次请求做五件事：

1. `GET /api/mistakes/<id>` 读这道题（服务没起时 `api.js` 会自己拉起）；
2. `agentPresets.resolve('mistake-review')` —— 顺带检查 `broken`：预设行在但 plugins 没激活成功时**当场拒绝**，而不是建一条没有工具的会话；
3. `agents.create({ sessionId, meta: { cwd, agentPreset }, agentOptions, setup })` —— `meta.agentPreset` 是落盘字段；`agentOptions` 必须自己带（取 `agentDefaultModel.currentSelection()`，缺了第一次请求就抛 `has no provider/model`）；`setup` 里先 `mount` 预设再让别的 scoped 注册；
4. `sessionTitle.rename()` 改标题为 `错题复习 · #12 · 极限`（服务没挂就如实降级 `renamed:false`）；
5. `agent.inject()` 注入首条消息：题目 / 我的答案 / 正确答案 / 解析 / 错因 / 知识点 / 已复习次数，让模型不用先调工具就知道在复习哪道。

两个容易踩的点：

- **不 dispose `AgentHandle`**：`dispose()` 会拆掉刚建好的会话，agent 归宿主 ctx 的生命周期。
- **`acquireScope` 给的是 `Symbol.asyncDispose` 租约，不是 `release()`**。漏还不会报错，但这条预设 revision 会一直有 user 挂着、永远 collect 不掉。第一版就写错成 `scope.release()`，被 `catch` 吞了，靠读 `dsh-agent-preset-registry` 源码才发现。

客户端拿到 `sessionId` 后只做一件事：`sessions.retain(sessionId, { source: 'mistakeBook' })`，用框架给的 `SessionProvider` 罩住，渲染 `renderFactorySlot('conversation.content', { variant: 'embedded', phase: 'active', hero: false })`。多轮、流式、滚动、草稿、Enter 发送全归宿主。

**`source` 绝不能写 `'mainView'`**：宿主的 ui-session / ui-layout 拿它判「谁是当前会话」，写错会把面板里的会话顶成主视图。

### 5.17.7 已知限制

- **面板只在根行加载成功时出现**：行名写成子路径、`exports["./client"]` 缺失、`dsh.client.platform` 不是 `web`，三者任一都会**静默不发现**——不报错、不提示，只是侧栏没有「错题」。
- **建会话依赖宿主服务**：`agentPresets` / `agents` / `agentDefaultModel` 任一缺席，路由返回结构化错误（`preset-unavailable` / `session-create-failed` / `model-unavailable`），面板把这句话原样显示在按钮下面。
- **面板不写题**：录入仍在网页 / CLI / 工具里做。面板只做「挑一道 → 看 → 评分 → 要 AI 带」。
- **代理只放行 `/api/*`**：将来面板要下载导出文件（`/api/export.csv` 这种要落盘的），得另开一条路由，不能顺手塞进 `?path=`。
- **上游状态码会被抹平**：代理一律回 200（成功）或 502（失败），原始 404 / 409 只出现在 message 里。面板只按「成功/失败 + 人话」处理，够用。
- **一次只嵌一条会话**：换一道题再点「让 AI 带我复习」会新建一条；旧的仍在会话列表里，标题以 `错题复习` 开头，可据此辨认。

### 5.18.3 B：结构化断点 + 事件流

**断点（`step`）**：评分时可选记「错在哪一步」，枚举 `审题 / 建模 / 计算 / 检验 / 表达 / 记忆`（[app.py](../../app.py) 的 `REVIEW_STEPS`）。

- **为什么是枚举不是自由文本**：只有固定词表才能聚合出「这个人在计算上反复失手」；自由文本每次写法不同，统计等于零。
- **落库**：`review_logs.step TEXT NOT NULL DEFAULT ''`，走 `MIGRATIONS` 自动补列；空串 = 不记录，老库无痛升级。
- **校验**：`_parse_step` 不在词表就 `VALIDATION_ERROR` 400，且**在变式入库之前**校验——坏请求不留垃圾。
- **聚合**：`analytics()` 出 `by_step`（哪一步错得最多）与 `step_patterns`（`知识点 × 步` 组合 ≥2 次，`LIMIT 10`）。
- **工具面**：`mb_weak_steps(days, limit)` 直接把这分布说给模型听。

**事件流（`events.ndjson`）**：建题 / 评分 / 斩题 / 恢复各写一行。

- **位置**：跟 `--db` 走——`PRAGMA database_list` 取主库目录，写同目录 `events.ndjson`。
- **为什么旁路不进表**：事件是「给模型和脚本看的流水」，不需要事务与索引；写失败 `except OSError: pass`，绝不拖垮建题 / 评分主流程。
- **读**：`GET /api/events?limit&kind&id`（取尾部 limit 条，坏行跳过）；`mb.py stream --ndjson` 直接吐行给管道。
- **工具面**：`mb_events(limit, kind, id)`。

### 5.19.2 代理层必须一起改

面板的请求都经宿主的 `/api/mistake-book/data` 转发（原因见 5.17.3）。原代理只放行 `GET`/`POST`，于是编辑（`PUT`）、删除（`DELETE`）、恢复（`POST`）里前两个直接 405。

- `proxy.js`：`methods` 扩到 `['GET','POST','PUT','DELETE','PATCH']`；非 GET/HEAD 时把请求体原样带给上游；`init.method` 透传。
- `?raw=1`：导出 CSV/JSON 回的是文件流而不是 `{ok,data}` 信封。新增 `api.js` 的 `callRaw()` —— 不解析 JSON、不拆信封，原样取 `{status, contentType, disposition, body}`，代理再把 `content-type` / `content-disposition` 回给浏览器，下载才会带文件名。
- `isAllowedPath` 没放宽：仍要求 `/api/` 开头、不含 `//`、`..`、`\`。

**为什么不在 `app.py` 里加 CORS 头**：那等于给「任意网页都能读写你的错题本」开口子；代理是白名单（只放本服务 `/api/*`），且复用宿主已有的鉴权与连接管理。

## 5.20 交互细节：统一下拉、每日上限、计划跳转（v0.24）

v0.23 把网页版搬进面板之后，用起来最硌手的是三件事：下拉框是浏览器原生的（在 DSH 侧栏里配色和字号都不跟、选项一多就溢出屏幕）、计划页的每日上限只有 10/20/50 三档、计划里的题点了没反应。这一版把这三处收掉。

### 5.20.1 18 处原生下拉 → 同一个 `Dropdown`

面板里原来有 18 个 `<select>`：新建/编辑表单 3 个（错因、难度、状态）、详情页断点 1 个、列表筛选抽屉 5 个（学科、状态、错因、时间、知识点）、批量修改 4 个（状态、错因、难度、标签方式）、学习页 1 个（学科）、再战区 1 个（学科）、计划页 2 个（窗口天数、学科）。

全部换成 `function Dropdown(props)`（`dsh-plugin/lib/client.js`），props 与原生 select 一一对应：

```js
h(Dropdown, {
  value, options: [{ value, label, disabled }],
  onChange, placeholder, disabled, title, className,
})
```

- **关闭态只渲染当前项**，弹层打开才挂 `role="listbox"`；选项 `role="option"` + `aria-selected`，选中项右侧打 `✓`。
- **键盘可达**：↑↓ 移动、Enter / Space 选中、Esc 关闭、点外部（document `mousedown` capture）关闭。
- 支持 `disabled` 选项（比如批量修改里当前筛选为空时的占位项）。

**为什么自己写而不是引组件库**：面板是纯 `h()` 渲染、零构建、零依赖，引一个 UI 库要连带打包器和样式体系；而「一个带键盘操作的下拉」总共不到 80 行，自己写反而更好控样式（要跟 DSH 侧栏的深浅色变量对齐）。

### 5.20.2 每日上限变成可存数字

原来是 `/api/plan?limit=10` 写死三档。现在：

- 后端 `settings` 新增键 `daily_limit`（`app.py` 的 `DEFAULT_SETTINGS` / `SETTING_BOUNDS` / `SETTING_LABELS`），范围 **1–200**，默认 **20**。
- `plan(conn, days=7, limit=None, subject="")`：`limit is None` 时读 settings；显式传值仍然优先（网页版「临时看一眼」、CLI `--limit` 都不受影响）。
- 面板计划页：数字输入框（`min=1 max=200`），失焦或回车提交，非法输入提示「请输入 1–200 的整数」并回滚；保存成功后刷新 `/api/meta`，切页签回来不会拿到旧上限。
- 网页版计划页同样换成数字输入框（`#pl-limit`），改完 PUT `/api/settings` 再重载计划；加载时用返回的 `daily_limit` 对齐输入框（没填/填错时能看到后端实际生效值）。
- CLI：`python mb.py settings --daily-limit 30`。

**为什么存后端而不是存 localStorage**：网页版与 DSH 面板是两个前端，localStorage 各存各的；存进 settings 后两边、CLI 看到的是同一个上限。

### 5.20.3 计划里的题可以点进去

计划页每行原来是纯 `div`。现在：

- 面板：`h('button.mb-hrow.pickable', { onClick: () => onOpen(item.id) })` → 切到「错题」页签、按 id 打开详情、详情顶部出现「← 返回计划」；点它回到计划页。
- 题目已被删除：详情页显示「这道题已被删除或不存在（id=N）」，而不是空白（`DetailPane` 里按 `/不存在/` 判 `error` 文案）。
- 题目不在当前筛选结果里：详情照常按 id 加载（详情是独立请求，不受列表筛选影响）。
- 网页版：计划卡片本来就是 `.card[data-id]`，点整行 `openEdit(id)` 进复习，行为不变。

**为什么用按钮而不是给 div 加 onClick**：`<button>` 自带键盘焦点与 Enter/Space 激活，不用自己补 `tabindex` 与 `role`。

- 网页版的下拉仍是原生 `<select>`（面板才换了 `Dropdown`）；两边视觉不统一，但网页版本来就是浏览器默认控件风格。
- 每日上限只在计划页能改，没有进「设置」面板（设置面板目前是再战区的折叠区）。

### 5.20.6 v0.24.1 修复：深色主题下弹层看不清字

**现象**：面板是深色主题时，下拉展开后选项几乎看不见。

**原因**：面板所有样式都用 `color:inherit` 跟随宿主主题，`--mb-*` 变量宿主并没有定义。弹层 `.mb-dd-pop` 写了 `background:#fff`（不透明白底），但没写 `color`，于是继承了宿主的浅色字 → 白底浅字，对比度约 1.1:1。原生 `<select>` 由浏览器自己画，所以换自定义组件之前没暴露这个问题。

**修法**：

- `.mb-dd-pop` 显式给 `background:#fff; color:#1c1c19`；新增 `.mb-dd-pop.dark{background:#24262a; color:#e9e9ec}`。
- 组件展开时读一次触发按钮的 computed color，`isLightColor()` 按相对亮度判断（>0.55 视为深色主题），决定加不加 `.dark`。拿不到颜色就按浅色兜底。
- 顺带把 `.mb-dd-empty` 也显式 `color:inherit`，避免占位文案同样看不清。

**回归测试**（`tests/test_client_render.mjs`，2 条）：`isLightColor` 对 `rgb(221,221,221)`/`rgba(255,255,255,.92)` 判真、对 `rgb(28,28,25)`/空串判假；再从 `client.js` 里正则取出 `.mb-dd-pop` 与 `.mb-dd-pop.dark` 的背景/前景色，按 WCAG 公式算对比度，要求都 ≥ 4.5:1（防止以后有人把 `color` 改回 `inherit`）。

### 5.20.7 v0.24.1 修复（二）：弹层被滚动容器裁掉

**现象**：编辑表单、详情区里靠下的下拉，展开后弹层只露出一条，或直接被切掉。

**原因**：`.mb-dd-pop` 是 `position:absolute`，会被最近的 `overflow:auto` 祖先裁剪。详情区与表单区都是 `overflow:auto`，弹层再高也超不出那个盒子。

**修法**：弹层改 `position:fixed`，坐标由触发按钮的 `getBoundingClientRect()` 现算：

- 下方空间 < 140px 且上方更宽裕 → **向上翻**；
- 高度取 `min(240, 可用空间)`，最小 80px（保证至少露 3 项）；
- 左边夹在视口内（`min(rect.left, vw - width - 8)`），宽度跟随按钮、不小于 120px；
- 展开期间挂 `scroll`（capture）与 `resize` 监听重算，关闭时解绑；
- 拿不到 `window` / 首帧还没坐标时退回 CSS 的 `absolute`，不闪不崩。

**为什么不用 `position:absolute` + 给祖先加 padding**：要动三层布局，且任何新加的滚动容器都会重新踩坑；`fixed` 一次到位。副作用是弹层脱离文档流，祖先若带 `transform`/`filter` 会重新变成定位基准——面板目前没有，将来加动效时要留意。

回归测试：`自定义下拉：拿到坐标后用 fixed 定位，避开滚动容器裁剪` 断言 `style.position='fixed'` 与 `top/left/minWidth/maxHeight` 透传；无坐标时 `style` 为 `null`（走 CSS 兜底）。

### 5.20.8 v0.24.1 修复（三）：「更多」菜单看不见

**现象**：点「更多 ▾」像是没反应——菜单要么一片白，要么只露出窄窄一条。

**原因有两个，叠在一起**：

1. **配色**：菜单是 `div.mb-panel` + 内联 `background: var(--mb-surface,#fff)`，只给了底色没给字色。宿主没定义 `--mb-surface`，于是白底；字色 `inherit` 到深色主题的浅色字 → 对比度约 1.2:1。和 5.20.6 的下拉是同一个病。
2. **定位**：菜单是 `position:absolute; right:0`，挂在按钮外层那个 `position:relative` 的 div 上。面板左栏最宽 340px，工具栏 `flex-wrap:wrap`，按钮会被挤到第二行**左端**；此时 `right:0` 让 150px 宽的菜单从 x≈-108 开始，几乎全在视口外。

**修法**：把弹层定位抽成一个共用 hook，下拉与「更多」菜单都走它——

```js
const { pos, dark } = usePopupAnchor(open, ref, selector, minWidth)
```

- `position: fixed` + 按触发元素的 `getBoundingClientRect()` 算坐标；下方不足 140px 且上方更宽裕时向上翻；
- `left` 夹在视口内，并给出 `maxWidth = vw - left - 8`——只夹 `left` 不够，菜单的自然宽度常常大于按钮宽度；
- 顺带按触发按钮的文字亮度决定深浅配色（`isLightColor`），返回 `dark` 给弹层挂 `.mb-pop.dark`；
- 弹层统一 `box-sizing: border-box`：`.mb-panel` 有 10px/12px 内边距 + 1px 边框，content-box 下 `max-width:150px` 实际会渲染成 176px，照样顶出边界；
- 「更多」菜单换成 `.mb-pop` / `.mb-pop.dark`（显式 `background` + `color`），补 `aria-haspopup` / `aria-expanded` / `role="menu"`；
- 补上**点外部收起**（原来只能再点一次按钮或点菜单项）。

**验证（Edge headless 实测，真实面板 CSS）**：

| 视口宽 | 按钮位置 | 菜单 | 是否完整在视口内 |
|---|---|---|---|
| 420 | 第一行右端 x=352 | x=262 w=150 | ✅ |
| 360 | 第二行左端 x=10 | x=10 w=150 | ✅ |
| 340 | 第二行左端 x=10 | x=10 w=150 | ✅ |
| 300 | 第二行左端 x=10 | x=10 w=150 | ✅ |
| 260 | 第一行右端 x=192 | x=102 w=150 | ✅ |
| 240 | 第一行右端 x=192 | x=82 w=150 | ✅ |

修复前 340px 下菜单是 `x=-108`、只露 68px；修复后深色配色 `#24262a` 底 / `#e9e9ec` 字。

回归测试：`更多菜单：展开后带 mb-pop 配色与定位，点外部能收起`（断言 `role=menu`、`.mb-pop`、三项文案）；对比度测试扩展到 `.mb-pop` / `.mb-pop.dark`，要求 ≥ 4.5:1。

## 5.21 三个「用起来会丢东西」的 bug（v0.24.2）

这一版没有新功能，只有三个会让人以为「数据没了」的缺陷。三个都是先用真实服务复现、再改的。

### 5.21.1 斩题之后找不到题

**现象**：在列表行上点「斩题」，这一行立刻消失，**没有任何提示**。用户不知道是删了、挂了还是没生效。

**原因**：`POST /api/mistakes/:id/suspend` 成功后前端只调了一次 `void load()`（网页版 `static/index.html` 的 `.then` 里同样只有 `load()`），列表按默认筛选重新拉取——而默认筛选**不含已斩题**，于是条目从视野里蒸发。找回的唯一途径是打开筛选抽屉勾「含已斩题」（面板里是 `filters.suspended`，请求参数 `suspended=all`；网页里是 `#show-suspended`），但这个入口在操作后毫无指引。

**修法**：斩题成功后不再「静默刷新」，而是弹一条提示条，给三个动作——

| 动作 | 行为 |
|---|---|
| 查看已斩题 | 勾上「含已斩题」并重新拉列表 |
| 撤销 | `POST /api/mistakes/:id/resume`，把题放回复习池 |
| 知道了 | 关掉提示条 |

面板：`client.js` 的 `ListTab` 新增 `notice` 状态与 `suspendItem` / `undo`，提示条是 `div.mb-notice`；网页：`static/index.html` 新增 `#flash` 条与 `flash(text, actions)`，列表与再战区的斩题都接上。恢复（`resume`）也会给一句「已恢复 #N 的复习。」

### 5.21.2 批量修改选「覆盖」必然 400

**现象**：面板里批量改标签，标签方式选「覆盖」，请求稳定返回 `400 {"error":{"message":"tags_mode 只能是 set / add / remove"}}`。

**原因**：面板 `BulkDialog` 的选项值写的是 `replace`，后端 `app.py` 的 `bulk_update` 只接受 `('set','add','remove')`。网页版一直是对的（追加到原有 / 替换原有 / 从原有移除），只有面板抄错了值。

**修法**：面板选项改为 `add` / `set` / `remove`，文案与网页版对齐；顺带把面板 `BulkDialog` 缺的两个字段补上——「来源」与「试卷」（网页版早就有，`meta.papers` 的字段名是 `name` 不是 `title`）。

实测三种模式：`set` / `add` / `remove` 均 200，`replace` 仍 400（后端保持不变，错的是调用方）。

### 5.21.3 批量导入：空行不分条 + 结果看不到

**现象一**：面板提示写着「用空行或 `---` 分隔」，但用空行隔开的两道题只入库了一条——**两道题的文本被拼成了一条**。

**原因**：后端 `parse_batch_text` 只按 `---` 切块，空行被当作段内换行。

**修法**：改成「空行也算分条」，但**不能无条件切**，否则长题干里的分段会被拆散。规则是：遇到空行时向后看第一个非空行，**只有当这一行是本块里已经出现过的字段键**（如已经出现过 `题目:`，下一段又以 `题目:` 开头）才切块；否则把空行原样留在题干里。同时修掉了「段内散行被丢弃」的问题——现在散行会接回题干，而不是静默丢字。

实测：

| 输入 | 结果 |
|---|---|
| `题目: 第一题` / 空行 / `题目: 第二题` | 2 条 ✅ |
| `题目: 长题干第一段` / 空行 / `第二段` / `答案: C` | 1 条，题干含两段 ✅ |
| `题目: 单题` / 空行 / `答案: 只在后面出现` | 1 条（`答案` 首次出现，不切） ✅ |

**现象二**：导入成功后弹窗**立刻关闭**，`setResult(...)` 写好的「成功 N / 失败 K」报告根本来不及显示。部分失败时，用户以为全成功了。

**修法**：`ImportDialog` 不再自动关窗，结果常驻显示「成功 N 条，重复跳过 M 条，失败 K 条」+ 逐条原因（第几段、为什么没导入、跟哪条重复），按钮变成「继续导入」/「完成」。一条都没解析出来时给一句可操作的提示：「每段请以「题目:」开头，段与段之间用一行 `---` 或空行分开」。

### 5.21.4 验证

- `python -m unittest discover -s tests` → **143 个测试全绿**（新增 `test_batch_import_blank_line_split`：空行分 2 条、长题干不拆、首次出现的键不切）。
- `node --test tests/test_plugin.mjs tests/test_tools.mjs tests/test_client.mjs tests/test_client_render.mjs` → **57 个全绿**（批量修改断言三档文案且不含「覆盖」、断言「来源」「试卷」；批量导入断言结果常驻与逐条明细）。
- 真实服务实测：空行分隔入库 2 条、长题干入库 1 条且两段都在；`bulk-update` 的 `set`/`add`/`remove` 全 200。
- 后端改动需要重启服务才生效（前端 `client.js` 刷新页面即可，网页版刷新即生效）。

## 5.22 面板里的公式渲染（v0.25）

**背景**：网页端 v0.20 就内置了 KaTeX，但只有组卷打印页真的调 `mbMath.render`；主界面一直按纯文本显示 `$...$`（见 5.15.1 的修正说明）。DSH 面板从 v0.23 起功能对齐网页，公式却完全没有 —— 高数、物理题的面板里全是一行行 `$\lim_{x\to 0}\frac{\sin x}{x}$`。v0.25 把这件事补上。

### 三条硬约束

| 约束 | 后果 | 采取的做法 |
|---|---|---|
| 改 `dsh-plugin/lib/proxy.js` 要重启 DSH | 用户正在用，重启成本高 | **一行都不改宿主半**，复用已有的 `?raw=1` 通道 |
| 不能加构建步骤、不能加 pip 依赖 | 面板是纯 ESM，没有打包器 | KaTeX 用现成的 `static/vendor/katex/katex.min.js`，动态插 `<script>` |
| 代理的 `callRaw` 用 `res.text()` 取回 | 二进制字体过文本通道会被破坏 | 用 **`output:'mathml'`**，只依赖浏览器原生 MathML，不需要 CSS 与 woff2 |

### 后端：一个只放行一个目录的只读口

`app.py` 新增 `GET /api/asset?path=...`（`_asset()`，[app.py](../../app.py) 2743 行）：

- 前缀白名单 `ASSET_PREFIX = "/vendor/katex/"`（[app.py](../../app.py) 37 行），别的路径一律 404。
- 三重穿越拦截：`..` / `\` / `//` 直接拒；再 `realpath` 确认落点仍在 `static/vendor/katex` 内。
- 按扩展名给 MIME（`.js` / `.css` / `.woff2` / `.woff` / `.ttf`），带 `Cache-Control: max-age`。

**为什么不直接让面板请求 `/vendor/katex/...`**：面板跑在 DSH 的 origin 下，直连 127.0.0.1:8000 是跨域；而且数据本来就要过宿主代理（见 5.17.3）。走 `/api/asset` 只多一层转发，不新增信任边界 —— 因为 `?raw=1` 通道本来就允许任意 `/api/*` 路径。

### 前端：一个 `MathText` 组件

`dsh-plugin/lib/client.js` 里新增一组函数（`errText` 之后）：

| 函数 | 作用 |
|---|---|
| `ensureKatex()` / `useKatex()` | 首次调用时插 `<script>`，用 `katexState`（0 未开始 / 1 加载中 / 2 就绪 / 3 失败）+ `katexWaiters` 通知订阅者 |
| `katexUrl()` | `DATA_ENDPOINT + '?raw=1&path=' + encodeURIComponent('/api/asset?path=/vendor/katex/katex.min.js')` |
| `texOf(src, display)` | `katex.renderToString(..., {displayMode, throwOnError:false, strict:'ignore', output:'mathml'})`，抛错时回落原文 |
| `mathHtml(text)` | 扫 `$...$` / `$$...$$`，不配对的 `$` 原样保留 |
| `applyMath(root)` | TreeWalker 就地替换文本节点，跳过已渲染的 `.katex` |
| `MathText` | 组件：`katexState === 2 && text.includes('$')` 时 `innerHTML = mathHtml(text)`，否则 `textContent = text` |

替换了 **10 处**：详情页题目 / 我的答案 / 正确答案 / 解析、列表行题面、变式题、学习页变式缺口、计划行、再战区与回收站的 160 字预览。

**为什么渲染器没就绪时先显示原文**：KaTeX 是 275KB 的脚本，面板首次打开时它还没到；此时显示 `$\frac{a}{b}$` 原文，脚本到了再由 `useKatex` 触发重渲染。比起「白屏等脚本」或「先显示加载中」，原文至少可读、可复制。

**为什么 `MathText` 的 children 仍传 `props.text`**：渲染测试用的假 React 会把 props 摊平成 `{tag, props, children}`，断言按 children 取文本；真 React 里 `innerHTML` 生效后 children 会被忽略，两边都不冲突。

### 验证

- `python -m unittest discover -s tests` → **146 个全绿**（新增 3 个：`/api/asset` 出 JS 且 `text/javascript` + `max-age` + 含 `katex`、出 CSS 且含 `@font-face`、六个坏路径全 404 `NOT_FOUND`）。
- `node --test ...` → **58 个全绿**（新增「公式块：渲染器未就绪时原样显示文本」）。
- 真实浏览器（Edge headless + CDP）实测：`/api/asset?path=/vendor/katex/katex.min.js` → 200 / `text/javascript` / 275414 字符；加载后 `katex.version` = `0.16.11`；`\frac{a}{b}+\sqrt{x^2+1}` 渲染出 `<math display="block">`、14 个 MathML 节点、包围盒 584×30；`innerText` 是 `𝑎 𝑏 + 𝑥 2 + 1`，**annotation 里的 TeX 源码不可见**（Chromium 只渲染 `<semantics>` 的第一个子节点）。
- 文本通道安全性：同一路径不带 `encodeURIComponent` 取回也是 200 / 275414 字符 / **0 个替换字符**；`/vendor/katex/../index.html` → 404。

### 已知限制

- 面板打开后约 100–300ms 才完成 KaTeX 加载，这段时间公式显示原文。
- 只认 `$...$` 与 `$$...$$`；`\[...\]`、`\\(...\\)` 不识别（和网页端 `math.js` 一致）。
- 网页主界面仍不渲染公式（有意，见 5.15.1）；要让网页也渲染，把 `esc(it.question)` 换成 `mbMath.render(it.question)` 即可，但会撑乱卡片行高。
- 后端改动需要重启服务才生效（`/api/asset` 是新路由）；前端 `client.js` 刷新页面即可。

## 5.23 面板对齐网页版：状态轨、缩略图、斩题回执（v0.26）

v0.25 之前面板和网页版还差五处「用起来能感觉到」的东西，这一版补齐。同时把两个功能维度**明确判死**：

| 项 | 决定 | 理由 |
| --- | --- | --- |
| 试卷维度（新建试卷 / 录题归卷 / 按卷筛选） | **不在面板补**（网页端保留） | 试卷是「一次考试的容器」，属于录入时的整理动作；面板是复习入口，录题仍走网页或批量导入。补进面板要加 3 个接口 + 1 个页签，收益只在录题那几分钟。 |
| 组卷打印 | **永久不做** | 打印是 A4 排版问题（分栏、页码、公式字体、图片缩放），不是面板能顺手带的功能；真要做应该是网页端打印页的延伸，不该塞进侧栏。 |

### 改动清单

| 改动 | 代码位置 | 说明 |
| --- | --- | --- |
| 列表左侧状态轨 | `client.js` `railOf()` / `.mb-item.st-*` | 逾期=红、已斩=灰、已掌握=深绿、复习中=中绿、未复习=棕。优先级：**逾期 > 已斩 > 掌握 > 复习中 > 新题**，与网页 `.card::before` 一致。 |
| 列表缩略图 | `client.js` `h('img.mb-listthumb', ...)` | 有 `image_file` 才画缩略图（v0.27 起 42×42），没图不留空位；列表请求本来就带 `thumbs=1`，后端多回的 `image_file` 之前被白扔了。 |
| 斩题回执 + 撤销 | `ArenaView` `suspend()` / `undo()` / `notice` | 以前点「斩题」行直接消失，用户不知道发生了什么。现在顶部出一条回执，带「撤销」（`POST /api/mistakes/<id>/resume`）和「知道了」。 |
| 变式缺口可点 | `StudyView` 的 `h('button.mb-hrow.pickable', ...)` | 学习页「这些题还没有变式」原来只能看，现在点了直接打开原题详情，回程条显示「← 返回学习」。 |

### 两个实现细节（踩过的坑）

## 5.24 面板视觉全部重做（v0.27）

### 为什么只动样式层

## 5.25 面板按视觉复核结果收紧（v0.28）

v0.27 的样式是「盲改」的 —— 当时 vision 后端不可用，只能靠猜。这一版先把视觉链路打通，用真实渲染的截图复核，再**按量到的数字**改。

### 复核方法（可复用）

`docs/harness/gen.mjs` 从 `dsh-plugin/lib/client.js` 里把 `CSS` 数组抽出来求值，拼成静态 HTML（浅色 / 深色各一份，420 / 900 / 1280 三种宽度），用 `vision_html_screenshot` 渲染成 PNG、`vision_describe` 让视觉模型点评，最后用 CDP（`Emulation.setDeviceMetricsOverride` + `Runtime.evaluate`）量真实数值。

> **教训**：视觉模型对「拥挤程度」和「颜色」的描述错得很离谱 —— 它说顶部占 30~35%（实测 8.1%）、说四个评分按钮是红橙绿蓝实心底（实测白底深字）。**结构和颜色必须用 CDP 量，视觉模型只用来找「感觉不对」的地方。**

| `app.py` `MAX_IMAGE_CHARS` | 2,800,000 字符 | **11,200,000** 字符（8MB × 4/3 再留点余量） |
| `app.py` `MAX_BODY` | 4MB | **64MB**（6 张 8MB 图 base64 后约 66M 字符，留出 JSON 外壳） |
| `dsh-plugin/lib/client.js` `addFile` | `> 2MB` 拒绝 | `> 8MB` 拒绝 |
| `static/index.html` `useImageFile` | `> 2MB` 拒绝 | `> 8MB` 拒绝 |
| 三条错误文案 | 「上限约 2MB」 | 「上限约 8MB」 |

### 5.28.2 为什么四道一起改

只改前端没用 —— 前端放行 8MB，`MAX_BODY` 还是 4MB 的话请求在 `Content-Length` 那一步就被挡掉；只改 `MAX_BODY` 不改 `MAX_IMAGE_CHARS` 的话单张还是在 normalize 里被拒。四道是串联的，必须一起抬。

`MAX_IMAGE_CHARS` 取 11.2M 而不是 8MB 整：base64 膨胀是 4/3，8MB 原图编码后约 11.18M 字符，留 2 万字符余量给 data URL 头。

### 5.28.3 验证

- 实测 `POST /api/mistakes`：5MB 图（Data URL 6,990,622 字符）→ **201**，落盘为内容寻址文件；9MB 图 → **400 单张图片过大（上限约 8MB）**
- node **64/64**、python **149/149** 全绿
- 服务已按新常量重启（Python 不热加载）

### 5.28.4 还没做的

- **没有压缩**：8MB 原图照样 base64 直传、原样落盘。真要把库压小，该在前端 canvas 缩到长边 1600px + JPEG 0.85，通常能从 8MB 降到 300~600KB。这一版没做，因为改的是「能不能导进来」，不是「省不省空间」。
- **请求体 64MB 是内存峰值**：`app.py` 是 `http.server` 单线程读满整个 body 再解析，6 张 8MB 同时提交时进程内存会短暂涨到 100MB 上下。个人本地用可接受，多用户部署要改成流式。

### 5.29.2 图片的两个 bug

1. **加载不出来**：面板所有请求都走 `dsh-plugin/lib/proxy.js` 的 `/api/mistake-book/data`。图片走的是 `raw=1` 分支，而 `api.js` 的 `callRaw()` 里是 `body: await res.text()` —— **把 PNG 的字节当 UTF-8 解码**，非法字节全变成 U+FFFD，前端拿到的必然是坏图。所以服务端 `GET /api/images/xxx.png` 单独测是 200 / 1,333,231 字节，面板里却是四个破图占位。
2. **跑到不该去的地方**：v0.32 重写详情页时，把 `item.images` 一次性全渲染在「题目」卡里，**丢掉了每张图的 `field`**。数据库里 `mistake_images.field` 一直是准的（`question` / `wrong` / `answer` / `analysis`），是前端没按它分组。

### 5.29.3 怎么修的

| 层 | 改动 | 为什么 |
|---|---|---|
| `app.py` | 新增 `image_data_url(path, max_side=1000, quality=82)`：装了 Pillow 就缩到 1000px 转 JPEG q82，没装就原样 base64 | 走普通 JSON 通道，**刷新页面即生效**；宿主插件（api.js/proxy.js）改了要重启 DSH，不能指望 |
| `app.py` | `images_of(conn, mid, with_data=True)` 给每条图片多带 `data`（data URL） | 详情页 `<img src={img.data}>` 直接显示 |
| `app.py` | `/api/mistakes?thumbs=1` 每行多带 `thumb`（220px / q78），`image_file` 仍然不对外暴露 | 列表缩略图也走同一条通道 |
| `client.js` | 详情页按 `field` 分四组：`question` / `wrong` / `answer` / `analysis`，没有 `field` 的老图和认不出的值都归题目 | 图片回到各自区块，不会凭空消失 |
| `client.js` | 列表缩略图 `item.thumb` → `image_url` → `image_file` 三级兜底；详情图 `onError` 退回 raw 通道 | 老数据、老 payload 都不炸 |
| `api.js` / `proxy.js` | `callRaw` 改 `Buffer.from(await res.arrayBuffer())`，同时返回 `body`（文本，CSV 用）与 `bytes`（二进制），raw 分支回吐 `got.bytes` | 根治二进制损坏；顺手让导出图片/备份也安全 |

### 5.29.6 点图放大（v0.32 补）

详情页四张图、录入表单里每块的缩略图，点一下都进全屏浮层：背景压黑到 82%、图片 `object-fit:contain` 不裁不变形、右上角圆形 × 关闭，Esc 和点背景也能关，打开时锁住页面滚动。

| 位置 | 改法 | 理由 |
| --- | --- | --- |
| `client.js` `openLightbox()` / `ensureLightbox()` / `hideLightbox()` | 命令式创建 `.mb-lightbox` 浮层，**不进 React state** | `DetailPane` / `ItemForm` 的 hooks 顺序被渲染测试的 seed 写死了，多一个 `useState` 就把测试全打翻；浮层本来也是「一次性 UI」，不需要参与渲染 |
| `client.js` `imgRow()` | `<a class="mb-thumb">` 加 `onClick`：`preventDefault` + `openLightbox(imgSrc(img))`，去掉 `target="_blank"` | **data: URL 的顶层跳转会被浏览器直接拦掉**，开新标签必然白屏；`href` 保留成兜底 |
| `client.js` 表单缩略图 | `.mb-fbthumb img` 加 `onClick` | 编辑已有错题时能先看清原图再决定删不删 |
| `static/index.html` | 同样一套 `.lightbox`，事件委托到 `.imgthumb img` | 网页端还在用，点缩略图不该没反应 |
