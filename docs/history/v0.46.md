# 5.43 词表操作先算后写、加搜索框、标签不再按空格切（v0.46）

## 5.43.1 问题：三件都长在「词表整理」这一块面板上

用户连着问了两轮「怎么删下拉里的值」，问到最后暴露出来的是三个独立的小毛病，凑在一起让这块面板**不好用也不敢用**：

| # | 现象 | 根因 |
|---|---|---|
| C | 标签写成「洛必达 法则」会变成两个标签 | `app.py` 的 `normalize()` 用 `re.split(r"[,，\s]+")` 切标签，**空格也算分隔符** |
| A | 点「删」立刻写库，事后才说「影响 N 道题」 | 合并/清空直接执行，没有预览；而词表操作**没有撤销**（回收站只管整道题） |
| D | 值一多只能滚着找 | 面板没有过滤框 |

其中 A 是最要命的：删错一个值，几十道题上的标签就没了，只能一条条改回去。

## 5.43.2 改了什么

| 位置 | 改动 |
|---|---|
| `app.py` `normalize()` | 标签切分改成 `re.split(r"[,，\r\n]+")`，空格不再当分隔符；顺手 `dict.fromkeys` 去重（`极限,极限` 只留一个） |
| `app.py` `_merge_samples()` | 新增：给前 5 道受影响的题返回 `{id, question[:60]}`，供确认条显示「如：求极限…」 |
| `app.py` `merge_knowledge()` / `merge_meta()` | 各加 `dry: bool = False`。dry 时**跑同样的匹配但不写库、不 commit、不登记别名**，返回里加 `dry: true` 与 `samples` |
| `app.py` 两条路由 | `/api/knowledge/merge`、`/api/meta/merge` 透传 `dry=bool(body.get("dry"))` |
| `dsh-plugin/lib/client.js` | 新增 `mergeCall(sources, to, dry)`；`apply(sources, to, force)` 先 dry 再等确认，`force` 才真写 |
| 同上 | 新增 `pending` 状态与确认条（`.mb-note.warn`）：写清「将把 N 项并到『X』，影响 M 道题（如：…）」，两个按钮「确认 / 取消」 |
| 同上 | 新增 `query` 状态与搜索框，`shown = query ? rows.filter(...) : rows` —— **只筛显示，不动已勾选的集合** |
| 同上 | CSS 加 `.mb-note.warn`（琥珀底 + 两端对齐），此前只有 `.mb-note` 与 `.mb-note.bad` |
| `dsh-plugin/package.json` | version `0.45.0` → `0.46.0`，`CLIENT_VERSION` 同步 |

## 5.43.3 为什么 dry 是同一个接口的参数，不是新接口

预览和真执行**必须用同一段匹配逻辑**，否则两边一漂，确认条上写「影响 3 道题」、真跑改了 5 道，比没有预览更糟。所以 `dry` 做成 `merge_knowledge` / `merge_meta` 的一个参数：同一个函数、同一遍遍历，只是 `if not dry` 决定要不要 `UPDATE`、要不要 `commit`、要不要登记别名。

代价是多一次 HTTP 往返（dry 一次 + 真写一次）。词表操作是低频动作，这个代价可以接受，换来的是「点之前就知道动的是哪几道题」。

顺带一个细节：`dry` 时**不登记别名**。别名是「以后写 `111` 自动落到规范名」的规则，dry 阶段就登记等于改了库，违背预览的定义。
