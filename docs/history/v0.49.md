# 5.46 示例与候选分离：推翻 v0.48（v0.49）

> 本文件是[错题本 README](../../README.md)的拆分文档。含 5.46 节。上一版见 [v0.48.md](v0.48.md)（**已被本版推翻**）。

## 5.46.1 为什么要整个推翻

用户的原话是「把上一轮 v0.48 的改动整体推翻——不是修补、不是微调，而是全部作废重来」。清点 v0.48 的 11 个改动文件后，真正的行为改动只有两处，其余是展示、测试和文档；而这两处里还有一处是等价改写，另一处（删掉 `SOURCE_HINTS`）只做了一半：常量没了，示例却硬编码进了前端。

于是 v0.48 留下了四个不自洽：

| # | 问题 | 位置 |
|---|---|---|
| 1 | `sourceOptions` 里 `.filter((f) => f && f.count > 0)` 恒为真，成了死代码 | `client.js:847-849` |
| 2 | 示例「如：期中 / 月考」硬编码在前端，比后端常量更难改、易与文档漂移 | `client.js` 的 `sourcePlaceholder` |
| 3 | 注释仍写「0 题的标『未使用』」，与实现矛盾 | `client.js:1904` |
| 4 | `meta()` 里 `sources` 的改写是等价的，没有独立价值 | `app.py` |

还有一处**冲突**必须先讲清：如果按字面「原样 revert」，那 8 个内置值（作业 / 练习册 / 周测 / 月考 / 期中 / 期末 / 模拟考 / 其他）会以 `count=0`、`system: true` 的形态回到 `source_facets`，在「词表整理」面板里重新变成**删不掉的幽灵行** —— 而那正是用户上一轮抱怨的东西。所以「推翻」不能等于「回退」，只能是换一个自洽的做法。

## 5.46.2 改了什么

核心一句：**示例与候选彻底分开**。候选只认库里真用过的值；示例是后端一个只读常量，只用来拼 placeholder。

| 文件 | 改动 |
|---|---|
| `app.py` | 新增 `SOURCE_EXAMPLES = ("作业", "练习册", "周测", "月考", "期中", "期末", "模拟考", "其他")`；`meta()` 多返回一个 `"source_hints": list(SOURCE_EXAMPLES)` |
| `app.py` | `_field_facets('source')` 行为不变（只返回 `[{"name","count"}]`），仅更新注释到 v0.49 措辞 |
| `dsh-plugin/lib/client.js` | `sourceOptions` 删掉恒真的 `count > 0` 过滤（死代码） |
| `dsh-plugin/lib/client.js` | `sourcePlaceholder` 改成 `(m) => ...`，从 `meta.source_hints` 里挑**还没用过**的写法（都用过了就取前三个） |
| `dsh-plugin/lib/client.js` | 词表整理面板上方注释同步为 v0.49 语义 |
| `CLIENT_VERSION` / `package.json` | `0.48.0` → `0.49.0` |

关键实现（`client.js`）：

```js
const sourcePlaceholder = (m) => {
  const hints = ((m && m.source_hints) || []).filter(Boolean);
  const used = {};
  ((m && m.source_facets) || []).forEach((f) => { if (f && f.name) used[f.name] = 1; });
  const unused = hints.filter((h) => !used[h]);
  const pick = (unused.length ? unused : hints).slice(0, 3);
  return pick.length ? '如：' + pick.join(' / ') : '';
};
```

两个细节：

- **示例不写死在前端**。常量在后端，前端只消费 `meta.source_hints`；改一次常量，placeholder 与文档不会漂移。
- **优先提示没用过的写法**。库里已有「作业」，placeholder 就显示「如：练习册 / 周测 / 月考」而不是重复已有的值 —— 这才是 placeholder 该干的事：提示你还能怎么写，而不是复述你写过什么。

## 5.46.3 为什么是「分离」，而不是回到 v0.47

| 方案 | 结果 | 结论 |
|---|---|---|
| A 原样回退 v0.47 | 8 个幽灵项回到管理面板，删不掉 | 否决，等于把用户抱怨的问题还回去 |
| B 示例与候选分离 | 面板只有真数据；placeholder 仍有示例；示例不落库、不参与合并 | **采用** |
| C 只回退展示层 | 死代码与矛盾注释留着 | 否决，属修补，不是推翻 |

顺带回答「示例会不会又要维护」：不会。`SOURCE_EXAMPLES` 是一个元组常量，没有状态、没有同步、没有治理界面 —— 它只被 `meta()` 读一次。新增一个写法示例就是改一行常量。
