# 5.44 批量修改从「八行表单」改成「一次一件事」（v0.47）

> 本文件是[错题本 README](../../README.md)的拆分文档。含 5.44 节。上一版见 [v0.46.md](v0.46.md)。

## 5.44.1 问题：八行「不改」

用户在面板里勾了几道题、点「批量修改」，看到的是一个八行表单：状态、学科、错因、知识点、难度、来源、试卷、标签，**每一行的默认值都是「不改」**。三个毛病叠在一起：

| # | 现象 | 根因 |
|---|---|---|
| 1 | 得扫完八行才知道这次能改什么 | 八个字段平铺，没有主次，也没有「我要改哪一项」这个前置选择 |
| 2 | 改完立刻关窗，连改两项要重新勾一遍题 | `onDone()` 里 `setBulkOpen(false)` + `setPicked({})`，一次操作只能做一件事 |
| 3 | 改了什么没有回执 | 只有一句 toast，关窗后就没了，改了三四项记不清哪项做过 |

结果是这个功能形同虚设：改一项要开一次窗、勾一次题，还不如逐条进详情页改。

## 5.44.2 改了什么

| 位置 | 改动 |
|---|---|
| `dsh-plugin/lib/client.js` `BULK_FIELDS` | 新增模块级常量：八个可改字段的 `{key, label, kind, hint}`，`kind` 决定值控件（`text` / `paper` / `status` / `type` / `level`） |
| `dsh-plugin/lib/client.js` `BulkDialog` | 整块重写。上半是「改哪一项」（下拉选字段）+「改成」（按 `kind` 渲染对应控件），下面一条「应用到这 N 道」，最下面是这次动过什么的流水 |
| `dsh-plugin/lib/client.js` 调用点 | 新增 `onApplied: () => { void load(); }` —— 应用成功后只刷列表，**不关窗、不清勾选** |
| `dsh-plugin/lib/client.js` `CLIENT_VERSION` | `0.46.0` → `0.47.0`（与 `package.json` 同步） |

四个细节：

- **候选复用 `/api/meta` 的 facets** —— 知识点用 `knowledgeFacets()` + `facetLabel()`（全角空格缩进 + 题量），学科 / 来源 / 标签用对应的 `*_facets`（带题量），跟录入表单看的是同一份数据，不会这里能选那里不能。`choices()` 与 `sourceOptions()` 定义在 `ItemForm` 内部，`BulkDialog` 用不到，所以本地重写了候选拼装。
- **标签有独立的方式开关** —— 选到「标签」时，第二个下拉从「改成」变成「标签方式」（追加到原有 / 替换原有 / 从原有移除），对应后端 `tags_mode` 的 `add` / `set` / `remove`。旧版这里是三个并排的小标签，现在跟字段选择同一层。
- **流水不落库** —— `log` 只是本窗口的 `useState`，关窗即失。够用：批量修改本身是即时生效的，流水只是让人在连做几项时不至于失忆。
- **后端一行没动** —— `POST /api/mistakes/bulk-update` 的契约（`{ids, fields}` → `{updated, ids, fields}`）与 `BULK_FIELDS` / `BULK_MAX_IDS` 全部照旧，这版纯前端。

## 5.44.3 为什么是「一次一件事」，而不是「八行折叠起来」

最省事的改法是把八行塞进一个折叠区、默认收起。没这么做，因为批量修改的真实场景是**几件独立的小事**：

> 把这 12 道题的知识点都改成「函数/单调性」，顺手状态改「复习中」，再把标签补一个「期中」。

这是三次互不相关的操作，不是一张要填满的表单。八行表单要求用户**先理解全貌再动手**；一次一件事只要求理解当前这一行。折叠只是把长表单藏起来，仍然得一次想清楚改哪几项、各自填什么。

配套的两件事让「连续操作」成本降到零：窗口不关（`onApplied` 只刷列表）、底下有流水（做完一项记一行）。

## 5.44.4 验证

`tests/test_client_render.mjs` 新增 / 重写 4 个用例（BulkDialog 的 hooks 顺序：`field, value, tagMode, log, busy, error`）：

| 用例 | 钉住什么 |
|---|---|
| 一次只改一件事，八行「不改」表单已去掉 | 出现「改哪一项」「改成」；**断言不出现「不改」**；八个字段名都在下拉里 |
| 标签有独立的方式开关，且与后端对齐 | 三个选项齐全，且**不含「覆盖」**（后端不认 `replace`） |
| 改完留在窗口里记流水 | 流水行「知识点 → 函数（2 道）」、「应用到这 2 道」、「完成」都在 |
| 字段切到标签时值控件换成方式开关 | 知识点档没有「追加到原有」，标签档有 |

- `node --test tests/test_plugin.mjs tests/test_tools.mjs tests/test_client.mjs tests/test_client_render.mjs` → **110 passed / 0 fail**
- `py -3 -m unittest discover -s tests` → **181 passed（9 skipped，本机已删网页版静态文件）**

面板里的实际形态：勾 3 道题 → 「批量修改 · 3 道」→ 改哪一项「知识点」→ 改成「函数/单调性」→ 点「应用到这 3 道」→ 列表刷新、窗口还在、底下多一行 `✓ 知识点 → 函数/单调性（3 道）` → 接着把「改哪一项」切成「状态」继续。
