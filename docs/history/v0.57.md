### 为什么「保存并继续」要清空表单，而不是保留

连续录同一章的题时，**学科/知识点/来源/错因/难度这五个字段确实是重复的**，但它们由 v0.50 的 `LAST_VALUES` 自动带出来（`emptyForm(null)` 里读 `reuse`），所以清空表单并不会让用户重填五遍 —— 真正要重填的只有题干、答案、解析、我的答案这些**每题都不同**的东西。这比「保留全部」更对：保留题干是最容易导致录重的一条路。

### 为什么重复检测只提醒、不拦截

学生手里真可能有两道长得一样的题（同一道题抄了两遍订正、或者两个变式只差一个数）。硬拦会逼他去改题干来绕过检测，等于把「数据干净」换成了「题干被写脏」。所以后端只在响应里多两个字段 `duplicate_of` / `duplicate_question`，面板显示成黄色提示条，用户自己决定要不要处理。

### 为什么 `exclude_id` 必须写进 SQL

第一版是在 Python 里比 `similar["id"] != cur.lastrowid`，看起来等价，实际永远不成立：查重发生在 INSERT **之后**，`ORDER BY id DESC` 第一个命中的就是刚插进去的那一行自己，于是「最像的一行」永远是自己，提示永远不会出现。测试直接抓到了这个 —— 改成 SQL 里的 `AND id <> ?` 才真的能比到别的题。
