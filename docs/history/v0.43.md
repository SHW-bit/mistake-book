# 5.40 活词表：让「来源」这类字段自己长齐（v0.43）

> 本文件是[错题本 README](../../README.md)的拆分文档。含 5.40 节。上一版见 [v0.31-v0.42.md](v0.31-v0.42.md)。

## 5.40.1 问题：下拉越长越乱，而且删不掉

用户反馈的原话是「像这种建的太多太乱了，怎么办」，截图是录入弹窗的**来源**下拉：8 项按 Unicode 码位排 —— 作业 / 其他 / 周测 / 月考 / 期中 / 期末 / 模拟考 / 练习册。查代码后确认这不是错觉，是三处设计叠在一起的结果：

| # | 位置 | 事实 | 后果 |
|---|---|---|---|
| 1 | `app.py:60` `SOURCE_HINTS` | 8 个内置值 | 每次都被并回候选 |
| 2 | `app.py` `meta()` | `"sources": sorted(set(sources) \| set(SOURCE_HINTS))` | **内置值删不掉**，删了下次请求又回来 |
| 3 | 同上 | `sorted()` 按码位 | 顺序与用量无关，「其他」排第二 |
| 4 | `_field_facets()` | 只认 `subject` / `tag` | 来源**没有计数、不能合并、不能删除** |
| 5 | `dsh-plugin/lib/client.js` | 四个字段都是裸 `<datalist>` | 面板里**没有任何词表管理界面** |

第 5 条是最要命的：v0.39 其实做过一套「合并 / 清理」面板，但只做在**网页版** `static/index.html` 里，而网页版已经弃用。用户唯一在用的 DSH 面板里，学科 / 知识点 / 标签 / 来源四个字段全是裸 datalist —— 能写不能管。

## 5.40.2 别人的做法（调研结论）

| 来源 | 关键做法 |
|---|---|
| [Stashmark 标签系统](https://docs.stashmark.app/docs/guides/managing-tags) | 候选**只来自已有标签**；最近用过置顶；**0 个书签的孤儿标签自动从建议消失**；`Settings > Tags` 有「总数 / 未使用数」统计条 + All/Unused 筛选 + 行内改名 + 勾选合并 + 删除 |
| [Stack Overflow 标签治理](https://stackoverflow.co/internal/resources/tagging-best-practices-strategy-and-maintenance/) | 要有明确的创建准则 + **把治理当成系统的一部分**长期维护 |
| [CityU 图书馆：受控词表 vs 自由文本](https://libguides.library.cityu.edu.hk/blogs/rssc_blog/home/Controlled-Vocabularies-vs-Free-Text-Keywords-Which-One-Should-You-Use) | 受控词表一致但维护贵，自由文本灵活但会脏；成熟做法是**混合**：自由输入 + 输入时引导 + 事后治理 |
| 本机 `_wn_study/`（wrong-notebook 源码） | `KnowledgeTag` 用邻接表做层级、九个学科各一份预置词表（`src/lib/tag-data/math.ts` 592 行）、`/tags` 管理页（学科 tab + 树 + 使用频率 Top20 + 新建/删除）；**但它的 `ErrorItem.source` 只是 `String?`，全项目 0 个文件引用** —— 别人的「来源」同样是裸文本、同样没人管 |

四条共识：①候选来自数据不是常量；②必须有集中管理页；③**合并优先于删除**；④系统预置与用户自建要分开；⑤版本升级要能重建系统词表。

## 5.40.3 改了什么（三处，共 4 个文件）

### A. 后端：`source` 升格为一等公民（[app.py](../../app.py)）

`_field_facets(conn, kind)` 增加 `source` 分支：

```python
if kind == "source":
    counts, last_used = {}, {}
    for name, total, stamp in conn.execute(
            "SELECT source, COUNT(*), MAX(updated_at) FROM mistakes "
            "WHERE source <> '' GROUP BY source"):
        counts[name] = counts.get(name, 0) + total
        last_used[name] = stamp or ""
    names = list(counts)
    names.sort()                                              # 名字
    names.sort(key=lambda x: last_used.get(x) or "", reverse=True)   # 最近用过
    names.sort(key=lambda x: -counts[x])                      # 题量（最外层，主序）
    used = [{"name": k, "count": counts[k], "system": k in SOURCE_HINTS} for k in names]
    unused = [{"name": h, "count": 0, "system": True}
              for h in SOURCE_HINTS if h not in counts]
    return used + unused
```

三次稳定排序是故意的：Python 的 `sort` 稳定，从内层到外层写就是「题量优先，同题量看最近用过，再同看名字」。**为什么不直接用 `ORDER BY count DESC, updated_at DESC, source`** —— 那样 0 题的 `unused` 就没法并进同一个列表（它不在 SQL 结果里），拆两段再拼更直白。

`meta()` 里原来的并集删掉，改成只给用过的：

```python
source_facets = _field_facets(conn, "source")
sources = [f["name"] for f in source_facets if f["count"] > 0]
# ...
return {..., "source_facets": source_facets, "sources": sources}
```

`merge_meta()` 的白名单从 `("subject", "tag")` 扩到 `("subject", "tag", "source")`，扁平值走同一条路径：

```python
if kind in ("subject", "source"):
    column = "subject" if kind == "subject" else "source"
    # 列名只从白名单取，不拼用户输入
    rows = conn.execute("SELECT id FROM mistakes WHERE " + column + " = ?", (name,))
```

> **为什么保留 `SOURCE_HINTS`**：新用户第一次录入时库里一个来源都没有，候选全空会让人不知道填什么。所以 8 个内置值不删，只是**降级成 placeholder 示例**（`如：期中 / 月考`）与 facets 里的 `count=0` 项，在管理面板的「未使用」里仍可见、可改名、可删除。

### B. 面板：新增「词表整理」折叠面板（[dsh-plugin/lib/client.js](../dsh-plugin/lib/client.js)）

学习页底部加一个 `<details>`，四个 tab（来源 / 学科 / 知识点 / 标签），每行是「复选框 + 名称 + `N 题` 或 `未使用` 徽标 + 内置标记 + 改名 + 删」，底部是「合并到（留空 = 清空勾选项）」+ 两个按钮。

- 来源下拉只列 `count > 0` 的值，label 带题量：`作业 · 3 题`。`choices()` 为此扩成同时接受字符串与 `{value,label}` 对象。
- 知识点走 `knowledgeFacets(meta)`，兼容旧的裸字符串数组，并按 `depth` 做 `paddingLeft` 缩进。
- 合并 / 清空按 kind 分流：knowledge → `POST /api/knowledge/merge`，其余 → `POST /api/meta/merge`，body 都是 `{sources, target}`。

### C. 录入：近似值当场提示

`nearName(value, names)` 用带提前返回的编辑距离（长度差 > limit 直接放弃，只比长度 ≤12 的值），在来源输入框下方渲染：

> 已有「期中」，用它更好：[用「期中」]

**为什么只提示不自动改**：自动改会把「期中考（区统考）」这种真·不同来源悄悄吃掉。提示是一句话的成本，误改是一条数据的成本。

## 5.40.5 没做的事

- **没有**把 `SOURCE_HINTS` 删掉或改成可配置（会破坏老库与文档里的引用）。
- **没有**做「最近用过的 3 个置顶」的独立 UI —— 排序里已经含「最近用过」，下拉顺序本身就体现了。
- **没有**动网页版（`static/index.html`）那套旧面板：网页版已弃用，本机文件也已删。
