## 5.50.1 四个问题

| # | 问题 | 现场证据 | 后果 |
|---|---|---|---|
| A | 安装脚本用 `new URL(import.meta.url).pathname` 取目录 | 该 API **不解码**百分号转义与中文 | 仓库放在 `D:\我的项目\mistake-book` 这类路径下，`node install.mjs` 直接 `ENOENT ... inst%20chk%...`；本机路径没有空格和中文，所以一直没暴露 |

## 5.50.2 改了什么

| 改动 | 位置 | 说明 |
|---|---|---|
| 安装脚本取目录 | `dsh-plugin/install.mjs` | `import { fileURLToPath } from 'node:url'`，`HERE = path.dirname(fileURLToPath(import.meta.url))` |
| `--quiet` / `MISTAKE_BOOK_QUIET` | `app.py` | 模块级 `QUIET` + `AppHandler.log_message` 覆写 + `main()` 的 `--quiet` |
| 搜索近似提示 | `dsh-plugin/lib/client.js` | 空态用 `nearName()`（v0.43 已有）在知识点 / 学科 / 标签候选里找编辑距离 ≤1 的名字 |
| `gc_images()` | `app.py` | 扫 `data/images/`，三处引用（`mistake_images.file` / `mistakes.image_file` / `trash.images`）都算在用 |
| `POST /api/maintenance/gc` | `app.py` | 默认 `dry=true` 只报数，必须显式 `{"dry": false}` 才删 |

| 面板入口 | `dsh-plugin/lib/client.js` | 「更多 ▾」→「清理图片」，先 dry 报「发现 N 张…可释放 X」，点「删掉它们」才真删 |

### 为什么 GC 默认 dry、还要认回收站里的图

删文件不可逆，而「哪些文件还在用」这个判断一旦有漏洞就是永久丢数据，所以默认只报数。真正的坑在引用集合：

1. `mistake_images.file` —— 一道题的图列表
2. `mistakes.image_file` —— 第一张图的冗余列（缩略图 / 打印 / 导出读它）
3. `trash.images` —— **回收站快照**。v0.52 起删题会清掉 `mistake_images` 行，但回收站里存了一份 `{file, field}` 清单，恢复时要靠这些文件。

漏掉第 3 条，结果就是「删一道带图的题 → 跑一次 GC → 从回收站恢复 → 图没了」。这条专门有测试
（`test_gc_images_keeps_files_referenced_by_trash`）。

### 为什么搜索提示用编辑距离而不是新写一个模糊搜索

后端 `build_filters` 的 `knowledge` 是 `LIKE %x%`，本来就能命中 `函数/单调性`（作为子串）—— 搜不到的是「用户把分隔符写没了」这一种。前端 `nearName()`（v0.43 为录入防同义值写的）正好是「编辑距离 ≤1 的已有名字」，`函数单调性` 与 `函数/单调性` 距离为 1，直接复用，一行都不用新写。提示条只给建议、不自动改词：用户点的才是他要搜的。
