### 冲突点（需你裁决，我不自行取舍）

**冲突 1：点卡片 = 编辑 vs 点卡片 = 复习。**
现状：点卡片直接打开编辑表单（index.html:1497-1498 → openEdit），复习是"打开表单后在底部点评分"。这与"错题本的主要动作是复习"矛盾，但改成"点卡片进复习、编辑走单独按钮"属于**交互变更**，超出"只改界面层"。要不要改？

**冲突 2：完全替换旧 UI vs 复用现有 DOM 契约。**
JS 里有约 76 个 class 名参与 innerHTML 拼装，改类名必须同步改 JS 模板字符串。这不影响功能，但"每批小步可回滚"会变难。我的做法是：**id 与事件绑定一律不动，只重排结构 + 换类名**。

## 2. 新 UI 方案

### 2.1 设计方向（假设，需你选）

- **方向 A（假设默认）"纸面"**：暖白画布 #f6f6f3、纯白卡片、墨色 #1c1c19、强调色墨绿 #2f6f4f、圆角 10/8/6、阴影几乎不用，靠描边和留白分层。
  理由：错题本是"学习本"，暖白 + 墨绿比冷灰 + 亮蓝更接近纸和笔，长时间看不刺眼。
- **方向 B "冷静"**：冷灰 #f5f6f8 + 纯白 + 深靛 #4a5bd8 + 8/6 圆角 + 极轻阴影。更接近现代 SaaS，与现有蓝色系连续。

两者都保留 v0.16 建立的"单一强调色 + 中性灰层级"原则，只换色相与圆角尺度。**在你确认前我按 A 做，改一行变量即可切到 B。**

### 2.2 信息架构

**一级导航 5 + 1**（回收站降级为次级入口，从顶部 tab 移走）：

学习 / 错题 / 计划 / 再战 / 分析 —— 回收站放在侧栏底部或"更多"里。

理由：现在 6 个 tab 等权，回收站这种低频页与错题并列，稀释了主路径。

**每页统一三段式**：

1. **PageHeader**：标题（16px/650）+ 一句状态摘要（"今天 12 道待复习，其中 3 道逾期"）+ 右侧主操作按钮
2. **FilterBar**：搜索框常驻（占 40%）+ "筛选"按钮 + 已选条件以可删 chip 回显 + 右侧视图动作（导入/组卷/导出收进"更多"菜单）
3. **Content**：列表 / 图表 / 树

理由：现在 11 个控件平铺一行（320-354），主操作（+新增错题）和导出链接混在筛选里，视觉上无法区分"筛"和"做"。

**布局壳**：

- 桌面（≥1024）：左侧 208px 侧栏（logo + 5 项导航 + 底部回收站/设置），主区 max-width 1040 居中，内边距 28px。
- 平板（768–1023）：侧栏收成 64px 图标栏。
- 手机（<768）：底部 5 个 tab 的 tabbar + 顶栏（标题 + 主操作），筛选面板改为底部抽屉。

### 2.4 组件划分

**基础组件（新写，10 个）**

Button（primary / ghost / danger / mini）、IconButton、Input、Select、Textarea、Checkbox、Chip、Badge（语义色，单一形态）、ProgressRing、Empty（带图标 + 一句引导 + 一个动作）

**业务组件（新写，9 个）**

PageHeader、FilterBar（含筛选抽屉）、StatCard、MistakeRow、DayGroup、KpCard、ReviewPanel（评分 4 档 + 遮答案）、VariantList、HistoryTimeline

**废弃**

| 废弃 | 原因 |
| --- | --- |
| nav.tabs 顶部横排 | 换成侧栏 / 底部 tabbar |
| .toolbar 平铺 | 换成 FilterBar + 更多菜单 |
| .overview 数字平铺 | 换成 StatCard |
| .badge 的 7 个变体 | 收成 1 个 Chip + 语义色，状态改用色点 |
| #list .card 特例覆盖 | 列表改用独立的 .row，不再复用 .card |
| .empty 纯文字 | 换成带动作的空态组件 |
| 弹窗 720px 单栏长表单 | 改两栏 + 分区（见 2.5） |

**复用（不动）**

- 所有 id、data-*、事件绑定、fetch 调用
- .revealbar 的交互概念（保留"先自己想再看答案"）
- .hist / .varbox 的信息结构，只重排视觉
- 分页逻辑、批量选择逻辑、图片粘贴逻辑
- dialog 元素本身（原生 dialog 继续用）

### 2.5 弹窗重做（唯一结构大改的地方）

现在是 700px 单栏，从上到下 14 个区块（学科→题目→答案→错因→标签→图片→评分→历史→变式→操作），滚动很长，复习时评分条在最下面，要滚很久。

新结构：**左 60% 题面区 + 右 40% 侧栏**（≥900px；窄屏堆叠）

- 左：学科/知识点/难度（一行元信息）→ 题目 → 图片 → 遮答案条 → 答案区（展开后）
- 右：评分面板（4 档，固定可见，不再藏到底部）→ 复习历史（紧凑 3 条 + 展开）→ 变式题
- 底部固定操作条：删除 / 已掌握 / 斩题 / 取消 / 保存

理由：复习是最高频动作，评分应该随手可点；编辑是低频，放侧栏。

### 2.6 视觉与交互规范

- 字号：标题 16/650、正文 13/1.55、辅助 12、元信息 11；行高比现在略松（1.55 vs 1.5）
- 控件：桌面 32px（现在 30），手机 40px
- 圆角：10（卡片）/ 8（控件）/ 6（徽标）
- 阴影：只用于弹窗和侧栏，列表靠 1px 描边
- 焦点态：统一 2px 强调色外环（现在只有输入框有）
- 动效：仅 120ms 的 background/border 过渡；不加位移和缩放
- 键盘：Tab 顺序按视觉顺序；弹窗内 Esc 关闭；列表行 Enter 打开
- 空态/加载/错误：三态都要有（现在是空的）
