# 复习闭环

一次只走一道题。五步，缺一步就不算复习完。

## 1. 取题

调 `mb_due`（默认未来 7 天，`limit` 控数量，`sort` 可选 created/due/stability/errors）。

- 用户说「我哪里弱」「哪科最差」→ 改调 `mb_stats` 的 `view: 'mastery'`，先给薄弱知识点，再取题。
- 用户点名某科/某知识点 → 调 `mb_search`（`subject` / `knowledge` / `tag`）。`knowledge` 默认**含子节点**，只想精确匹配传 `kdeep: false`；只找没归类过的题传 `nokp: true`。
- 用户问「我总在哪一步错」→ `mb_weak_steps(days=30)`；要流水账 → `mb_events(limit=20)`。
- 没有到期题就直说，不要编题凑数。

## 2. 读题，但别看答案

`mb_get(id)` 默认**不给正确答案和解析**，输出里只有题干、学生当时的错答、错因、分类和复习历史。这是故意的：你先看见答案，讲题时就会不自觉地把思路往答案上带，学生也就没机会自己提取一次。

- 顺带看一眼「已有变式（N 条）」——出变式时别和已有的重复。
- **学生答完之前不要传 `reveal: true`。**

## 3. 让学生先作答

把题干原样给出（数学式子用 `$...$`），问一句：「这题你当时怎么想的？现在重做一遍。」

- 学生答对思路 → 进第 4 步。
- 学生答错或卡住 → 先指出他错在哪一步（拿 `my_answer` 和 `error_reason` 对照），**不要直接念解法**。

学生没开口就把解题步骤讲完，这一轮复习等于白做。

## 4. 出变式题，并当场入库

在原题基础上换数字、换条件、换问法，**保持同一个知识点**。一题即可，不要一次给三道。

变式题要存进错题本，否则下次复习它又不见了：判分时连同变式一起交给 `mb_review`（第 5 步），`variant_question` 必填，`variant_answer` / `variant_knowledge` 可选。重复的变式会被自动去重，不用自己判。

出完等学生作答，答完再判。

## 5. 判分并回写

判分前可以 `mb_get(id, reveal: true)` 取解析对照——这是整轮里**唯一**该看答案的地方。

按学生对**变式题**（没出变式就按原题）的表现给评分，调 `mb_review`：

| 表现 | rating |
| --- | --- |
| 完全不会 / 又错了同一处 | `again` |
| 想起来一半，仍需提示 | `hard` |
| 独立做对 | `good` |
| 秒答且能说清为什么 | `easy` |

同时记下**错在哪一步**（`step`，六档：审题 / 建模 / 计算 / 检验 / 表达 / 记忆）。

- 判断不出来就别填，瞎填比不填更糟。
- 口径：式子列对但算错 → 计算；看错或看漏条件 → 审题；思路搭不起来 → 建模；答案对但写不出过程 → 表达；会做但记不住公式 → 记忆；算完没检查 → 检验。

评分是给**原题**的（变式只用来测），所以 `id` 用第 1 步拿到的题号。

回写后念一句下次复习时间（`mb_review` 会返回），再问「继续下一道？」。

## 学生新错的题

复习中如果学生暴露了**另一道**题的错误，用 `mb_add` 记下来：

```
mb_add(question=..., my_answer=..., answer=..., analysis=...,
       subject=..., knowledge=..., mistake_type=..., source='复习')
```

`mistake_type` 只能取：概念不清 / 计算失误 / 审题错误 / 方法不会 / 粗心 / 其他。

## 边界

- 一次一轮，不要连着出五道题。
- 判分要严：`good` 是「独立做对」，不是「听懂了解法」。
- 学生要求直接看答案时给，但看完仍要 `mb_review`（按 `again` 或 `hard` 记），不要跳过回写——跳过等于这道题白复习。
- 不要在开头把整份复习计划一次铺给用户；走完一道再说下一道。
